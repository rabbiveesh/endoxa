## Refuted beliefs (calibration + entrenchment references)

_Beliefs a later verdict declared WRONG — a misread of the code, or a hunch since refuted. Each was held at some `asserted` confidence and then defeated; that (asserted vs structural-envelope vs outcome) is the B5 calibration datum (§3a): confident-and-wrong is the signal an epistemic store must keep. There is no gold here — a verdict is itself a revisable belief (some are later overturned; see verdict-of-a-verdict). These are NOT supersessions — the refuted belief was never true, so it carries no valid_time; only the `adjudicates` edge defeats it._

- ❌ `subprocess-isolation-needed` (asserted **0.8**, d=inferred) — adjudicated false by `subprocess-isolation-removed`: VERDICT: subprocess isolation was REMOVED (#14). The IPC + serialization overhead was real and the crash-isolation worry never materialized; in-process parsing with Rayon (274-file Mojolicious in 204ms) is both faster and simpler.
- ❌ `dispatch-always-resolvable` (asserted **0.75**, d=inferred) — adjudicated false by `honest-miss-over-guessing`: VERDICT: guessing a dispatch target when the invocant is unresolved produced WRONG go-to-definition jumps. NAV now records an HONEST-MISS instead — a wrong jump is worse than no jump, so 'best-effort guess' was actively harmful.
- ❌ `memo-coarse-receiver-key-sound` (asserted **0.85**, d=inferred) — adjudicated false by `coarse-memo-key-unsound-diamond`: VERDICT (soundness review, fixed 2026-06-03): the coarse memo key was UNSOUND. ReturnExpr::Receiver substitutes the FULL receiver, so one shared MethodOnClass{Parent, m} attachment reached with ClassName('Foo') then ClassName('Bar') served Foo's memoized answer to Bar — a SILENT wrong type. The cycle-guard could share the coarse key (collision→None, conservative) but a memo returning a substantive value on it could not. Fix: key the receiver on full structural identity.
- ❌ `doc-parse-stdin-double-dash` (asserted **0.85**, d=stated) — adjudicated false by `parse-stdin-is-single-dash`: VERDICT: FALSE. The stdin sentinel is a SINGLE dash: `cli_parse` does `if path == "-"` (src/main.rs:1105), and the binary's own usage help even prints "(`-` reads from stdin)" (line 150). `--parse --` would try to open a file literally named `--`. CLAUDE.md is wrong about its own debugging command.
- ❌ `doc-max-fold-debug-only` (asserted **0.8**, d=stated) — adjudicated false by `max-fold-runs-in-release`: VERDICT: FALSE. The fold has a `debug_assert!` (dev-only) AND a separate unconditional `if iters >= MAX_FOLD_ITERATIONS { eprintln!("...bailing out..."); break; }` that runs in RELEASE too — the code's own comment even calls it 'the all-builds safety net'. CLAUDE.md's 'debug-only' contradicts the code and the code's comment.
- ❌ `haiku-transitive-parents-break-guard` (asserted **0.99**, d=inferred) — adjudicated false by `transitive-parents-ends-on-empty-stack`: VERDICT: partly wrong — the COUNT is right (21 out, depth=21) but the MECHANISM is wrong: with no grandparents the stack empties after 21 pops, so `while let Some(p) = stack.pop()` ends normally; the `if depth > 20 { break; }` guard NEVER fires here. - ❌ `haiku-refs-nonopen-single-scan` (asserted **0.95**, d=inferred) — adjudicated false by `refs-nonopen-scans-twice`: VERDICT: FALSE. A not-open workspace module is scanned TWICE — once in the WORKSPACE phase (covered_paths only excludes OPEN files) and again in the DEPENDENCY phase, which has no covered_paths skip. Both phases run collect_from_analysis independently.
- ❌ `haiku-dedup-fails-mixed-key` (asserted **0.98**, d=inferred) — adjudicated false by `dedup-normalizes-keys`: VERDICT: FALSE — no such bug. key_for_sort normalizes BOTH FileKey::Path(p) and FileKey::Url(u) to the same PathBuf (u.to_file_path(), falling back to PathBuf::from(u.as_str())), so Url/Path for one file sort ADJACENTLY and file_key_eq (also via key_for_sort) treats them equal; dedup_by removes them correctly.
